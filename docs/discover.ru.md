# Обнаружение реле Zelio Logic через USB

[Read in English](discover.md)

Команда `zelio discover` считывает данные с работающего Zelio Logic через USB
и готовит конфигурацию MQTT-моста для чтения. Протокол исследован на реле
Schneider Electric **SR3B261FU** с модулем расширения **SR3XT141FU** и кабелем
программирования **SR2USB01**. USB-транспорт рассчитан на Linux, в том числе
Raspberry Pi OS, и macOS. Поддерживаемая версия кабеля определяется по USB
`16de:0084` и `bcdDevice=0600`.

## Подключение реле

1. По инструкции Schneider Electric подключите кабель SR2USB01 к разъёму
   программирования реле, а USB-штекер вставьте в компьютер, на котором будет
   работать `zelio`. Со стороны реле у кабеля специальный разъём Zelio.
   [Карточка кабеля](https://www.se.com/uk/en/product/SR2USB01/usb-pc-connecting-cable-for-smart-relay-zelio-logic-3-m/)
   · [Ответ Schneider Electric о выборе кабеля](https://www.se.com/uk/en/faqs/FA23076/)
2. Соберите `zelio`. В Linux установите правило udev, добавьте пользователя
   в группу `zelio` и переподключите USB-штекер после того, как новое членство
   в группе вступит в силу. На macOS соберите программу с libusb для
   архитектуры компьютера и разрешите подключение, если система запросит
   доступ. [Сборка](../README.md#quick-start) · [Доступ к USB в Linux](install.md#linux-usb-access)
   · [Настройка macOS](install.md#macos)
3. Остановите MQTT-мост и закройте Zelio Soft и другие программы, работающие
   с кабелем. Команде нужен эксклюзивный доступ к USB-интерфейсу через libusb.
   Если в Linux интерфейс занят, проверьте `lsusb -t`.
   [Диагностика подключения](install.md#diagnose-a-connection)
4. Оставьте реле в режиме RUN и откройте на его экране страницу входов и
   выходов, чтобы мост мог считывать их состояния. Выполните `bin/zelio list`
   и скопируйте серийный номер USB-кабеля. При переносе кабеля на другое реле
   проверьте программу и соответствие входов и выходов на новом реле.

## Создание конфигурации для чтения

Подставьте вместо `SERIAL` серийный номер кабеля, выберите уникальный
идентификатор устройства в MQTT и укажите адрес брокера MQTT 5. По умолчанию
идентификатор формируется из серийного номера, а брокер ожидается на том же
компьютере. Учётные данные брокера передавайте через переменные окружения.
[Настройка MQTT](install.md#mqtt-setup)

```sh
bin/zelio discover --serial SERIAL --device-id zelio_lights \
  --mqtt-url mqtt://127.0.0.1:1883 --config-out zelio.json
```

Команда печатает JSON-отчёт со сформированной конфигурацией в поле `config`.
Флаг `--config-out` сохраняет эту конфигурацию в новый файл. Если файл уже
существует, команда не перезаписывает его. Если нужно сравнить результаты
после обслуживания реле, сохраните отчёт локально. В нём могут содержаться
идентификаторы и сведения о работающей программе.

Созданная конфигурация публикует подключённые в схеме выходы `Q` в виде
бинарных датчиков. Перед запуском проверьте идентификаторы, имена и метки
каналов. В том же формате можно добавить входы для чтения.
[Пример конфигурации](../config.example.json)

Метки `Q` показывают логическое состояние выходов. Срабатывание нагрузки
проверяйте по самой нагрузке или по независимой обратной связи. Обнаружение
читает данные без подачи импульсов, принудительной установки выходов, переноса
программы и переключения реле между RUN и STOP. [Описание протокола](protocol.md)

```sh
bin/zelio validate --config zelio.json
bin/zelio serve --config zelio.json
```

`validate` проверяет конфигурацию. Сверьте метки на работающем реле и
убедитесь, что Home Assistant показывает соответствующие состояния. Для
постоянной работы используйте инструкции по запуску через systemd или в
macOS. [Руководство по установке](install.md)

## Проверка кандидатов на управление в FBD

Поиск охватывает ограниченное подмножество скомпилированных схем FBD. Тип
`toggle_candidate` означает, что обнаружена связь через вход переключения
бистабильного блока. Поле `outputs` перечисляет подключённые в схеме выходы
`Q`, а `routes` описывает возможные связи сигналов FBD с этими выходами. Для
каждой связи указаны идентификатор сигнала `signal_id`, блок `block` и тип
связи `kind`. Физический вход `input`, затронутые выходы `outputs` и пояснение
`reason` указываются, если их удалось определить. В `reset_outputs` перечислены
выходы, для которых удалось проследить путь от физического входа сброса,
активного при логической единице. Если формат программы распознан и в схеме
есть подключённые выходы, команда может создать конфигурацию для чтения даже при
наличии связей `reset` или `unresolved`. При неподдерживаемых или неполных данных
программы команда завершится с ошибкой.

Сравнивайте поля `program_sha256` и `config.cable_serial` в отчётах. Отпечаток
представляет собой хеш SHA-256 данных программы, которые совпали при двух
чтениях через USB. При каждом подключении к кабелю команда `serve` сверяет
`fbd_sha256` из конфигурации с программой реле.
При несовпадении устройство становится недоступным, а `serve` повторяет
попытку подключения. Повторите проверку после изменения программы или
переноса кабеля на другое реле.

Сверьте связь `toggle_candidate` с программой реле и физическим выключателем.
Для группы трековых светильников посмотрите, какие выходы `Q` и нагрузки
меняют состояние при нажатии выключателя. Логические состояния смотрите
через мост для чтения или на экране реле. Если связь остаётся неясной,
оставьте режим чтения.

Сигнал общего выключения проверьте отдельно как сброс нескольких выходов.
Если его `reset_outputs` пересекается с выбранной группой, команда добавит
физический вход этой связи в список `block_when`. Мост блокирует команды,
пока этот вход активен. Неоднозначные связи сброса проверьте отдельно.

## Проверка одного переключателя перед внедрением

Остановите работающий мост и создайте пробную конфигурацию с одной выбранной
связью и отдельным идентификатором устройства в MQTT. Передайте в
`--expect-program` значение `program_sha256` из отчёта, по которому сверяли
связи. Пробная конфигурация управления создаётся при совпадении отпечатка.
Вместо `SIGNAL_ID` подставьте `signal_id` из отчёта в десятичном формате или
в шестнадцатеричном с префиксом `0x`. Флаг `--verified-signal` явно разрешает
выбранную связь в пробной конфигурации.

```sh
bin/zelio discover --serial SERIAL --device-id zelio_pilot \
  --mqtt-url mqtt://127.0.0.1:1883 --expect-program PROGRAM_SHA256 \
  --verified-signal SIGNAL_ID --config-out zelio-pilot.json
bin/zelio validate --config zelio-pilot.json
```

Перед запуском моста проверьте метки выбранных выходов `Q` и входы
в `block_when`, если они есть в файле `zelio-pilot.json`.

```sh
bin/zelio serve --config zelio-pilot.json
```

Отправляйте команды с пробного переключателя в Home Assistant по одной. После
каждой команды сверяйте логические состояния и фактическое срабатывание
нагрузок. Выбранные выходы `Q` должны измениться одновременно, а остальные
остаться в прежнем состоянии. Проверьте включение и выключение, верните
исходное состояние и остановите пробный мост. Для связей, не прошедших
проверку, оставьте режим чтения. [Настройка Home Assistant](../README.md#home-assistant)

Когда все выбранные связи пройдут проверку, сформируйте конфигурацию в новом
файле с рабочим идентификатором устройства. Повторите `--verified-signal` для
каждой проверенной связи. Наборы выходов `Q` у выбранных связей должны быть
непересекающимися. Проверьте файл командой `validate` и запустите мост.
[Настройка импульсного управления](momentary-control.md#configure-the-bridge)

Если обнаружение завершилось с ошибкой или мост показывает недоступные
каналы, проверьте версию кабеля, режим RUN и страницу входов и выходов на
экране реле. Команда `bin/zelio probe --serial SERIAL` проверяет кабель, а
`bin/zelio monitor-io --serial SERIAL` проверяет логическое состояние входов и
выходов реле. [Диагностика подключения](install.md#diagnose-a-connection)
